## 0. Context the executor needs (verified by the planner)

- `src/features/map/style/sharecropr-basemap.json` is a **template**. `src/features/map/config/basemap.ts::resolveBasemapStyle()` replaces `{{TILE_ORIGIN}}` and `{{BASEMAP_ARCHIVE}}` at runtime. The archive name comes from `app.config.ts` (`process.env.BASEMAP_ARCHIVE ?? 'sharecropr-basemap-202608.pmtiles'`), and `basemap.ts` has the same fallback. **Do not change that mechanism in this package**, and do not edit `basemap.ts`, `app.config.ts` or `MapCanvas.tsx`. So "never latest" is enforced in three places: on the template, on both defaults, and on the env override (see the validator).
- The style today has 5 layers (background, water, landuse, roads, buildings). It has no symbol layers, and the declared `sprite` is never used.
- **Protomaps basemap source-layer names.** I checked these against `@protomaps/basemaps@5.7.2` `dist/basemaps.js`, the canonical style for the v4 tiles that the Protomaps build produces. The names are `boundaries, buildings, earth, landcover, landuse, places, pois, roads, transit, water`. The existing layers already use valid names. Feature properties used below: `kind`, `name`, `name:en`, `min_zoom`, `capital`. Protomaps' own default fonts are `Noto Sans Regular | Medium | Italic`. Its sprite icon names are `townspot` and `capital` for places, and the POI `kind` value for POIs, except `station` → `train_station`.
- `scripts/tile-build.sh` is a stub: `protomaps build` is commented out and not a real command. Its archive name is `sharecropr-basemap-${YYYYMM}.pmtiles`, and the validator regex matches that. Fixing the build belongs to SCRUM-22, not here.
- **Validator package.** `@maplibre/maplibre-gl-style-spec` is already in the lockfile at **24.8.5** as a transitive dependency of `@maplibre/maplibre-react-native@11.3.6`. `npm view` shows `latest` is 26.4.4. **Pin the devDependency to exactly `24.8.5`** (published 2026-05-05) so that we validate against the spec version the native renderer ships with. 26.x could accept properties MapLibre Native here does not support. The package exports `validateStyleMin`, and the bin `gl-style-validate` is already linked in `node_modules/.bin`.
- CI/CD §4.1 already names the gate `npm run ci:validate-map-style` and lists its three assertions: schema-valid, own hosts only, one dated archive and never `latest`. TC-GEO-48 is the matching test. Use that script name.

Keep our additions to **one** package.json script line, **one** devDependency line and **one** app.yml step, each in a *different* hunk from WP-04's (placement given below). It is recorded below as an asset requirement for SCRUM-22.

### Validator (`scripts/validate-map-style.mjs`) asserts

1. No `latest` (case-insensitive) anywhere in the style template.
2. `glyphs` and `sprite` start with `{{TILE_ORIGIN}}/`. `glyphs` contains `{fontstack}` and `{range}`. Every source URL is on `{{TILE_ORIGIN}}`. `sources.basemap.url` is exactly `pmtiles://{{TILE_ORIGIN}}/{{BASEMAP_ARCHIVE}}`.
3. The defaults in `app.config.ts` and `basemap.ts` are equal. The effective archive (`$BASEMAP_ARCHIVE` or the default) matches `^sharecropr-basemap-\d{6}\.pmtiles$`. `TILE_ORIGIN` is https.
4. The style with placeholders filled in passes `validateStyleMin` from the pinned style-spec.
5. SCRUM-24 complexity floor:
   - at least one symbol layer with `icon-image`
   - at least 2 distinct `text-font` stacks
   - every `source-layer` comes from the Protomaps set
6. Exit 1 with `map-style: …` lines on any failure. On success it prints one `map-style: ok — …` summary.
